# Academy Live

জুম-এর মতো একটা লাইভ ক্লাসরুম ওয়েব এপ — ভিডিও/অডিও কল, স্ক্রিন শেয়ার, লাইভ অ্যানোটেশন, চ্যাট এবং ক্লাস রেকর্ডিং সহ। এটি [LiveKit](https://livekit.io) (ওপেন-সোর্স, স্কেলেবল WebRTC SFU) এর উপর বানানো, যাতে ৫০+ জন স্টুডেন্ট নিয়ে ঘণ্টার পর ঘণ্টা লাইভ ক্লাস চলতে পারে।

## ফিচার

- **ওপেন টিচার অ্যাক্সেস** — কোনো প্রি-সেট শিক্ষক তালিকা বা শেয়ার্ড পাসকোড লাগে না। যেকোনো শিক্ষক নাম, ইমেইল ও নিজের একটা রুম পাসওয়ার্ড দিয়ে সাথে সাথে ইউনিক ক্লাস বানাতে ও হোস্ট হতে পারেন।
- লাইভ ভিডিও/অডিও, মাইক/ক্যামেরা টগল, স্ক্রিন শেয়ার
- **লাইভ ড্রয়িং/অ্যানোটেশন** — শিক্ষক শেয়ার করা ডকুমেন্টের ওপর দাগ দিতে পারবেন, যা প্রতিটি স্টুডেন্টের স্ক্রিনে (মোবাইল সহ) ডকুমেন্টের ঠিক সঠিক জায়গায় দেখাবে। টুলবক্স শুধু শিক্ষকের জন্য।
- **ফুলস্ক্রিন ও স্ক্রল/আঁকা মোড টগল** — স্ক্রিন শেয়ার হলে ম্যানুয়াল ফুলস্ক্রিন বাটন, এবং শিক্ষকের জন্য "আঁকা" বনাম "স্ক্রল/ইন্টারঅ্যাকশন" মোডের মধ্যে টগল
- **ড্র্যাগেবল ফ্লোটিং ক্যামেরা** — স্ক্রিন শেয়ারের সময় সবার ক্যামেরা ভিউ ছোট, ভাসমান প্যানেলে থাকে, যা টেনে সরানো ও মিনিমাইজ করা যায়
- বিল্ট-ইন চ্যাট
- **ব্রাউজার-সাইড রেকর্ডিং** — কোনো S3/ক্লাউড স্টোরেজ ছাড়াই, শিক্ষকের ব্রাউজারের `MediaRecorder` দিয়ে সরাসরি তার ডিভাইসে `.webm` ফাইল ডাউনলোড হয়
- হোস্ট প্যানেল: পার্টিসিপ্যান্ট তালিকা, কাউকে মিউট বা ক্লাস থেকে বের করে দেওয়া
- মোবাইল ব্রাউজার সহ যেকোনো ডিভাইসের ব্রাউজার থেকে কাজ করে

## ধাপ ১: LiveKit সেটআপ

আপনার নিজের মিডিয়া সার্ভার লাগবে। সবচেয়ে সহজ উপায়:

1. [cloud.livekit.io](https://cloud.livekit.io) -এ ফ্রি অ্যাকাউন্ট খুলুন (ফ্রি টায়ারে শুরু করা যায়; ৫০+ জন/লম্বা ক্লাসের জন্য পেইড প্ল্যান লাগতে পারে — তাদের প্রাইসিং পেজ দেখুন)।
2. একটা প্রজেক্ট বানান, সেখান থেকে **API Key**, **API Secret**, এবং **WebSocket URL** (`wss://...`) কপি করুন।
3. (ঐচ্ছিক, নিজের সার্ভারে চালাতে চাইলে): LiveKit নিজে সেলফ-হোস্ট করাও যায় — দেখুন [self-hosting docs](https://docs.livekit.io/home/self-hosting/deployment/)।

## ধাপ ২: এনভায়রনমেন্ট ভ্যারিয়েবল

`.env.local.example` কপি করে `.env.local` বানান এবং মান বসান:

```bash
cp .env.local.example .env.local
```

```
LIVEKIT_API_KEY=...
LIVEKIT_API_SECRET=...
LIVEKIT_URL=wss://your-project.livekit.cloud
NEXT_PUBLIC_LIVEKIT_URL=wss://your-project.livekit.cloud
```

**ব্যস, এটুকুই।** কোনো `TEACHERS` তালিকা বা শেয়ার্ড হোস্ট-পাসকোড সেট করার দরকার নেই — প্রতিটা শিক্ষক নিজের জন্য নিজস্ব রুম পাসওয়ার্ড দিয়ে ক্লাস শুরু করেন, যা LiveKit রুমের মেটাডেটায় (হ্যাশ করা অবস্থায়) সেভ থাকে; আলাদা কোনো ডেটাবেসও লাগে না।

রেকর্ডিং এখন সম্পূর্ণ ব্রাউজার-সাইডে হয় (`MediaRecorder` API দিয়ে) — তাই এর জন্য আলাদা কোনো env variable বা ক্লাউড স্টোরেজ লাগে না।

## ধাপ ৩: লোকালি চালানো

```bash
npm install
npm run dev
```

তারপর ব্রাউজারে `http://localhost:3000` খুলুন। একই লিংক দুইটা ব্রাউজার ট্যাব/ডিভাইসে খুলে টেস্ট করুন (একজন হোস্ট, একজন স্টুডেন্ট হিসেবে)।

## ধাপ ৪: ডিপ্লয় করা

সবচেয়ে সহজ: [Vercel](https://vercel.com) -এ ডিপ্লয় করুন —

1. এই কোডটা একটা GitHub রিপোতে পুশ করুন।
2. Vercel-এ রিপো ইম্পোর্ট করুন।
3. উপরের এনভায়রনমেন্ট ভ্যারিয়েবলগুলো Vercel প্রজেক্ট সেটিংসে যোগ করুন।
4. Deploy চাপুন — একটা পাবলিক লিংক পাবেন যা শিক্ষক ও স্টুডেন্ট সবাই ব্যবহার করতে পারবে।

(Netlify, Render, বা যেকোনো Node.js হোস্টিং-এও চলবে, যেহেতু এটা একটা স্ট্যান্ডার্ড Next.js অ্যাপ।)

## কীভাবে ব্যবহার করবেন

- **নতুন ক্লাস শুরু (শিক্ষক)**: হোমপেজে "নতুন ক্লাস শুরু করুন" ট্যাবে নাম, ইমেইল ও একটা রুম পাসওয়ার্ড দিয়ে "ক্লাস শুরু করুন" চাপুন — সাথে সাথে ইউনিক ক্লাসরুম তৈরি হয়ে হোস্ট হিসেবে জয়েন হয়ে যাবেন। ক্লাসের ভেতরে হেডারে "🔗 স্টুডেন্ট লিংক শেয়ার করুন" চাপলে শেয়ারযোগ্য লিংক কপি হবে।
- **আগের ক্লাসে ফিরে আসা (শিক্ষক)**: অন্য ট্যাব/ডিভাইস থেকে বা রিলোড করার পর হোস্ট হিসেবে ফিরে আসতে "আগের ক্লাসে ফিরুন" ট্যাবে রুম আইডি, নাম ও একই পাসওয়ার্ড দিন।
- **স্টুডেন্ট**: শিক্ষকের দেওয়া লিংকে ক্লিক করলে হোমপেজে রুম আইডি অটো-পূরণ হয়ে যাবে — শুধু নাম দিয়ে "ক্লাসে জয়েন করুন" চাপুন।
- **অ্যানোটেশন**: শিক্ষক স্ক্রিন শেয়ার করলে ডকুমেন্টের ওপরে ডান পাশে একটা টুলবার আসবে — "✏️ আঁকা চালু" চাপলে আঁকা যাবে, রং/লাইনের আকার বদলানো যাবে, "মুছুন" দিয়ে সব মুছে ফেলা যাবে। "🖱 স্ক্রল/ইন্টারঅ্যাকশন" মোডে থাকলে ক্যানভাস আঁকা বন্ধ করে পেজ স্ক্রল/ক্লিক স্বাভাবিকভাবে কাজ করবে। স্টুডেন্টরা শুধু আঁকা দেখতে পাবে, টুলবার দেখবে না।
- **রেকর্ডিং**: শিক্ষক "● রেকর্ডিং শুরু করুন" চাপলে ব্রাউজার একটা ট্যাব/উইন্ডো বেছে নিতে বলবে — এই ক্লাসের ট্যাবটি বেছে নিন। "রেকর্ডিং বন্ধ করুন" চাপলে বা ব্রাউজারের নিজস্ব "Stop sharing" চাপলে, ফাইলটি (.webm) সরাসরি ডাউনলোড হয়ে যাবে।

## সীমাবদ্ধতা ও পরের ধাপ

এটি একটি কার্যকর MVP (Minimum Viable Product) — Zoom-এর সব ফিচার (ব্রেকআউট রুম, ওয়েটিং রুম, পোল, হোয়াইটবোর্ড, ক্যালেন্ডার ইন্টিগ্রেশন, নেটিভ মোবাইল এপ) এতে নেই। যা আছে তা দিয়ে ৫০+ জনের ৩+ ঘণ্টার লাইভ ক্লাস, লাইভ অ্যানোটেশন, চ্যাট, স্ক্রিন শেয়ার ও রেকর্ডিং পুরোপুরি চলবে।

কিছু গুরুত্বপূর্ণ সীমাবদ্ধতা যা জানা দরকার:

- **রেকর্ডিং ব্রাউজার সাপোর্ট**: `MediaRecorder` + ট্যাব-রেকর্ডিং (`getDisplayMedia`) Android/ডেস্কটপ Chrome, Edge, Firefox-এ ভালো কাজ করে। **iOS Safari-তে ট্যাব-রেকর্ডিং সমর্থিত নয়** — সেখানে রেকর্ডিং বাটন লুকানো থাকবে ও একটা বার্তা দেখাবে। এটা ব্রাউজারের সীমাবদ্ধতা, আমাদের কোডের বাগ নয়। আইফোনে রেকর্ডিং দরকার হলে বিকল্প হলো সার্ভার-সাইড (LiveKit Egress + ক্লাউড স্টোরেজ) রেকর্ডিং যোগ করা, অথবা শিক্ষক ফোনের নিজস্ব স্ক্রিন-রেকর্ডার (iOS Screen Recording) ব্যবহার করা।
- **রেকর্ডিং শুধু "যা স্ক্রিনে দেখা যাচ্ছে তা" ধারণ করে** (ব্রাউজার ট্যাবের ভিডিও+অডিও), সার্ভার-সাইড কম্পোজিটিং নয় — তাই মান নেটওয়ার্ক/ডিভাইসের ওপর নির্ভর করে।
- **`/api/moderation` রুট প্রোডাকশন-হার্ডেনিং দরকার** — এখন শুধু হোস্ট UI-ই এই এন্ডপয়েন্ট কল করে দেখায়, কিন্তু সার্ভার নিজে caller-এর টোকেন যাচাই করে না। আরও কড়াকড়ির জন্য caller-এর LiveKit token থেকে `roomAdmin` গ্র্যান্ট যাচাই করা উচিত।
- **রুম পাসওয়ার্ড হ্যাশিং হালকা (HMAC-SHA256 + সার্ভার সিক্রেট পেপার)** — সাধারণ ক্লাসরুম ব্যবহারের জন্য যথেষ্ট, কিন্তু bcrypt/argon2-এর মতো ধীরগতির হ্যাশ নয়। খুব উচ্চ-নিরাপত্তা দরকার হলে সেটা বদলানো যায়।

স্বাভাবিক পরবর্তী ধাপগুলো:

- **নেটিভ মোবাইল এপ** — React Native + LiveKit RN SDK দিয়ে বানানো যায়, একই ব্যাকএন্ড/টোকেন সার্ভার পুনরায় ব্যবহার করে।
- **ওয়েটিং রুম / অ্যাটেন্ডেন্স** — জয়েন করার আগে হোস্টের অনুমোদন, এবং কে কতক্ষণ ক্লাসে ছিল তার লগ রাখা (ডাটাবেস লাগবে, যেমন Postgres)।
- **ব্রেকআউট রুম, হ্যান্ড রেইজ, পোল** — LiveKit-এর data channel ব্যবহার করে কাস্টম বানানো যায় (অ্যানোটেশন ফিচারও একই কৌশলে বানানো হয়েছে)।
- **সার্ভার-সাইড রেকর্ডিং ব্যাকআপ** — যাদের iOS থেকে রেকর্ডিং লাগবে, তাদের জন্য আগের LiveKit Egress + S3 পদ্ধতি ফিরিয়ে এনে ব্রাউজার-রেকর্ডিং-এর পাশাপাশি একটা "ব্যাকআপ" অপশন হিসেবে রাখা যায়।

## খরচ সম্পর্কে

LiveKit Cloud-এর একটা ফ্রি টায়ার আছে, কিন্তু ৫০+ জনের ৩ ঘণ্টার ক্লাস নিয়মিত চালালে এটা প্রতি মিনিট/participant হিসেবে বিল হবে — তাদের বর্তমান প্রাইসিং [livekit.io/pricing](https://livekit.io/pricing) পেজে দেখে নিন যাতে মাসিক খরচ আন্দাজ করতে পারেন। খরচ কমাতে চাইলে নিজের সার্ভারে LiveKit সেলফ-হোস্ট করা যায় (একটা ভালো VPS/ক্লাউড সার্ভার লাগবে)।
